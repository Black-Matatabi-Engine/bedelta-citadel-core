## Q4. AI 進入 DeFi 的範式轉移 — 尚未被想過的防禦面

### 協議 Owner 真正看到的變化（不是「機器人比較快」）

1. **意圖密度爆炸：** 人類一天 10 筆；Agent 一秒 10 筆。風控從「審交易」變成「審策略圖」。
2. **幻覺是新的 oracle 攻擊：** LLM 把 1.05 寫成 105、把 bps 當百分比——這不是價格操縱，是 **數量級投毒**。
3. **跨場協同是預設，不是進階：** Agent 天然會走 Pendle→GMX→HL。單場熔斷不夠，必須 **跨場 R20**（`demo:matrix --loop=all` 的政治意義在此）。
4. **Gas 不再是剎車：** 0-Gas / AA / session key 讓「失敗成本 ≈ 0」，攻擊者可以窮舉土壤。

### 尚未被認真做的兩個防禦地平線

#### A. AI-to-AI Poisoned Collusion（Rogue A 困住 Agent B）

```text
Agent A (rogue)                  Agent B (victim)
    │                                 │
    ├─ seed thin Camelot tick ────────┤
    ├─ advertise "deep PT pool" ──────► B enters
    ├─ pull liquidity / widen tick ───┤
    └─ B soil-passes on stale depth ──► sandwich / lock
```

**缺口：** 今日 `checkSoilResistance()` 看 **單意圖向量**，不看 **對手 Agent 的近期流動性操作圖**。沒有「對家是 Agent、剛抽池」的 collusion bit。

**方向（未實作，勿對外宣稱）：** 短窗流動性 \(\Delta L / \Delta t\) + 對手地址 Agent 標籤 → `FLAGS_COLLUSION` → 全場 FAIL_CLOSED。

#### B. Multi-Block MEV Hallucination Exploits

Agent 把「三步原子策略」拆成 **可預測的多塊序列**（Pendle mint → GMX increase → HL hedge）。Searcher 不需要搶同一塊，只要 **讀公開意圖圖** 就能在塊 \(n+1\) 夾塊 \(n+2\)。

**缺口：** 單筆 soil 可能 PASS；**序列本身** 是 MEV 廣播。無 multi-block intent commitment / 亂序閘。

**方向：** 意圖圖 hash + 最大公開領先時間；超窗則 `severSigningChannel()`。這與 Flashbots 敘事對齊，**比再加一個 DEX adapter 更能拉 Inno。**

## Q7. Blackhat 視角 — 關鍵漏洞、遺漏與邊角

> 本節假設攻擊者 **讀過** `risk-engine-core.ts` bitmask、`checkSoilResistance()`、`severSigningChannel()`、以及 `demo:matrix`。目標是 **讓毒流通過 ALLOW** 或 **在熔斷後仍能簽名**。

### Edge Case 1 — Oracle Delay Spoofing / Timestamp Manipulation

**攻擊：** 向 Worker / CLI 餵 **過期 RPC**：深度仍顯示 \(500\,\mathrm{k}\) USD，實際池已被抽空；或把 `at` / block timestamp 撥回 soil 窗口內。

**現況緩解：**

- Pendle 路徑有 **60s oracle TTL**（Sentinel）；超窗 FAIL_CLOSED。
- Sequencer / soft-confirmation / gas-guard 在 **完整 payload builder** 路徑存在；Worker **lean 熱路徑** 已把重型 audit builder 移出 fetch（69.28 KiB）→ **Edge 健康端點不再即時打 RPC**。這是 bundle 勝利，也是 **新攻擊面**：攻擊者打的是 **KV / stub 新鮮度**，不是 citadel-metrics。

**殘餘：** 純 TS soil 若呼叫方傳 `disableThresholdJitter: true` + 自訂 `at`（demo 即如此），**單測 harness 可偽造時間**。生產必須強制 `Date.now()` / L2 block time，禁止呼叫方自帶時鐘。Bitmask 不存「時鐘信任」；這是 **輸入完整性** 問題，不是 flag 問題。

**中和：** `SystemState` 不因 ALLOW 而「記住舊深度」。每次意圖重算。Nonce / session expiry 不直接修 RPC 時鐘；要修的是 **probe 時間源 SSOT**。

### Edge Case 2 — Multi-Tx Split-Payload Poisoning（拆單過 0.35）

**攻擊：** 單筆 GMX 意向 \(I=0.36\) 會 trip。拆成 3 筆 \(I=0.12\) 的子單，每筆低於 `GMX_IMBALANCE_MAX = 0.35`，在 **無持倉累加** 的 mock 裡會 3× ALLOW。

**現況緩解：**

- 不變量是 **池狀態** \(I=\lvert L-S\rvert/(L+S)\)，理論上應讀 **執行後 OI**，不是單筆 notional。
- 若適配器每次都傳 **全市場 OI**，拆單無效。
- 若 Agent 只傳 **本筆 size**、OI 用過期快取，拆單 **有效**。

**殘餘：** Vitest / demo 使用靜態 `oiLongUsd` / `oiShortUsd`。Blackhat 在 **快取延遲 + 並行三 Worker** 下可賽跑。`FLAGS_IMBALANCE_TRIP` 是 **單次評估**，沒有 **滑動窗口累加暴露**。

**中和（未全落地）：** `SystemState` 應累加 `pendingOiDelta`；R20 一旦 trip 全場斷簽。現況 R20 在 soil trip **之後** 由 `severSigningChannel()` 手動/顯式呼叫（`demo:matrix` Step 3）。**生產熱路徑必須讓 soil trip → 自動 R20**，不能依賴 demo 編排。

### Edge Case 3 — Off-Chain Hot Key Replay（60s cooldown 後重放 EIP-712）

**攻擊：** 攔截 ALLOW 階段的 session / EIP-712 簽名；等 cooldown 結束、CRI 恢復，**重放同一簽章** 打進 Gate 或 HL L1。

**現況緩解：**

- `severSigningChannel()` 置 `signingChannelOpen: false` + `hardlock` + CRI→0；後續 `gateStatus` 全 FAIL_CLOSED。
- Session key 有 **expiry / clip**；consume-once Gate 敘事存在於合約層。
- HL 適配器檢查 `sessionKeyValid`。

**殘餘：**

- **Off-chain 簽名若未綁 nonce + chainId + 意圖 hash + 過期塊**，cooldown 後重放是教科書攻擊。
- Worker lean 路徑 **不跑** 完整 grant-audit / 意圖帳本 boot（`ensureIntentPersistenceBoot` 已移出 fetch 熱路徑以換 69.28 KiB）。這表示 **Edge GET 健康檢查不再順便恢復 2PC ledger**。攻擊者不打 GET；打的是 **scheduled / 簽名管線是否仍持有舊允許的 bytes**。
- `0x1111/0x2222` bootstrap 使「輪換熱鑰」故事在鏈上不可信——攻擊者可假設 **同一 guardian EOA 長期有效**。

**中和：**

| 機制 | 對 Replay 的作用 |
|------|------------------|
| `SystemState.hardlock` / R20 | 本地進程內斷熱路徑；**不跨 Worker isolate 共享**（無 DO 則多實例可分叉狀態） |
| bitmask `FLAGS_SEVERED` | 單次評估拒絕；需寫入持久 nonce |
| EIP-712 nonce + Gate `verifyAndConsume` | **真正** 的一次性；合約未與 PolicyGuard 同 receipt 時，Off-chain 重放窗口仍在 |
| 60s cooldown | 降頻，**不是** 密碼學一次性 |

**Blackhat 結論（給主席）：** Citadel 對 **單意圖、單進程、誠實時鐘** 很硬。對 **快取 OI、多實例狀態、可重放離線簽、拆單累加** 仍是 **中等**。834 PASS 精確證明 harness 閉環，**不證明** 上述三邊角在 42161 上不可用。
